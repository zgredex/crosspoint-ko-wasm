# oracle/

The record of what this project is pinned to, and how conformance against it is measured.

| file | what it is |
|---|---|
| `crosspoint-ko.pin.json` | the pinned reference revision plus the per-file audit (byte-identical / divergent / absent), generated — never hand-edited |
| `fixtures/*.epub` | deterministic conformance fixtures (Korean prose, ruby, mixed runs), generated by `scripts/verify/make_conformance_fixtures.py` |

**One fixture is not in this repo.** The full gate also runs `web/demo.epub`, a commercial Korean
book used for the end-to-end measurement (1,690 pages, 71 image pages). It is deliberately untracked
— this repo does not redistribute it — so a fresh clone cannot reproduce those exact numbers. The
gate **skips it with a note** rather than failing; every other fixture is in the tree, and a fixture
that is missing when it should be present still fails the gate.

The portable fixtures are the three generated ones plus `web/demo-images.epub` and
`web/demo-png.epub` (this project's own image-decoder test books), which together cover CJK
breaking, ruby, rules, styled runs and both image decoders.

The contract, the evidence and what is *not* covered: **`docs/ko-oracle-conformance.md`**.

## What is pinned

`crosspoint-reader-ko/crosspoint-reader-ko` @ `release/korean`
`84a39194dfce1ebd772ac9163df0a59daa0d72dc`, scope `lib/Epub/** lib/EpdFont/** lib/GfxRenderer/**`.

## Running the gates

```sh
# 1. source contract — is the vendored engine still the pinned one?
#    needs gh auth for the fresh tree; a cached tree can be passed with --tree-json
KO_ORACLE_SRC=<pinned checkout> python3 scripts/verify/oracle_pin.py --check
# The conformance wrapper accepts the same cached tree when GitHub auth is unavailable:
KO_ORACLE_TREE_JSON=/tmp/pinned_tree.json scripts/verify/oracle_conformance.sh --quick

# 2. behaviour contract — does the port LAY OUT the same as the reference?
bash scripts/verify/oracle_conformance.sh            # all fixtures
bash scripts/verify/oracle_conformance.sh --quick    # text fixtures only
bash scripts/verify/oracle_conformance.sh --sensitivity   # must FAIL — proves the gate can
```

## Getting the pinned checkout (needed by gate 2 and by the sensitivity control)

```sh
R=crosspoint-reader-ko/crosspoint-reader-ko
S=84a39194dfce1ebd772ac9163df0a59daa0d72dc
mkdir -p /tmp/up-src && gh api "repos/$R/tarball/$S" | tar xz -C /tmp/up-src
# → /tmp/up-src/crosspoint-reader-ko-crosspoint-reader-ko-84a3919
```

`oracle_conformance.sh` expects it at
`/tmp/up-src/crosspoint-reader-ko-crosspoint-reader-ko-84a3919/lib`; override with
`KO_ORACLE_CMAKE_ROOT=<checkout>/lib`.

## Re-pinning (only after re-auditing the divergence)

```sh
git -C <checkout> fetch && git -C <checkout> log --oneline -1 <new-sha>
KO_ORACLE_SRC=<new checkout> python3 scripts/verify/oracle_pin.py --write --tree-json /tmp/new_tree.json
python3 scripts/verify/oracle_report.py     # paste the table into docs/ko-oracle-conformance.md
bash scripts/verify/oracle_conformance.sh   # the new revision must pass before it is the pin
```

A pin bump is a typography change until the conformance gate says otherwise. Never move the
pin to make a failing comparison pass — that is the one thing this directory exists to
prevent.

## Landmine

Two engine files (`blocks/TextBlock.cpp`, `parsers/ChapterHtmlSlimParser.cpp`) include
`"../../../../src/fontIds.h"` — a **relative** path that assumes the engine sits four levels
below a directory containing `src/`. `vendor-lib/` and the reference checkout both satisfy
that; any copy of the engine placed elsewhere must bring a `src/` along or the build fails
with a missing-header error. `UPLOAD: scripts/verify/oracle_conformance.sh` handles this for
the sensitivity copy.
